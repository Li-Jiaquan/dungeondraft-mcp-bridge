# Dungeondraft MCP

[English](README.md) · 简体中文

这个项目让 MCP 客户端操作正在运行的 Dungeondraft：查询地图和素材、绘制地形与建筑、设置灯光、导入本地 PNG、管理楼层，并保存或导出地图。

项目包含两部分：`mod/` 中的 Dungeondraft 扩展在软件内监听本机 `127.0.0.1:8787`；`server/` 中的 Python MCP 服务通过标准输入输出向客户端提供工具，再把绘图指令发给扩展。两者只在本机通信。

本项目基于 [Brandon Florian 的 dungeondraft-mcp](https://github.com/brann-dev/dungeondraft-mcp) 扩展。原作者的 MIT 许可及版权声明保留在 [LICENSE](LICENSE) 中。

## 功能

- 查询地图、楼层、物件和已加载素材；用画面捕获或全图导出检查绘制效果。
- 绘制物件、墙、路径、门窗、屋顶、图案地板、洞穴、水域和材质。
- 使用四种或八种地形槽，填充区域、柔化笔刷以及沿路径绘制道路；八槽混合统一归一化。
- 新建、复制、切换、排序和对照楼层，设置绘图层，并以悬崖、贴图和光照表达高低地。Dungeondraft 在这里没有可调用的三维高度场。
- 设置环境光与独立光源的颜色、亮度、范围和阴影。使用原生灯光纹理和墙体遮挡。
- 导入本地 PNG 作为可编辑位置、大小和图层的图片物件；图片数据会嵌入地图文件。整张图片不会自动变成独立地形和墙体。
- 将地图保存为原生 `.dungeondraft_map`，导出 PNG、JPEG、WEBP 或 Universal VTT。
- 通过 `native_targets`、`native_describe`、`native_get`、`native_set`、`native_call` 探查当前安装版本开放的原生接口；通过 `ui_tree`、`ui_action` 访问原生控件。

通用原生接口有版本和数据类型边界；发现可用方法不代表每个原生按钮和参数都经过验证。原生调用和部分批量操作没有统一自动撤销，建议先保存地图副本。

## 安装

需要 Dungeondraft 1.2.0.1（当前实测版本）、Python 3.10 或更新版本，以及一个支持本地标准输入输出服务的 MCP 客户端。

1. 把 `mod/dungeondraft-mcp-bridge/` 复制到 Dungeondraft 的 Mods 目录，在软件中启用 **MCP Bridge**，然后打开一张地图。
2. 在项目根目录创建虚拟环境并安装服务：

   ```powershell
   py -3 -m venv .venv
   .\.venv\Scripts\python.exe -m pip install -e .\server
   ```

3. 在 MCP 客户端中注册 `\.venv\Scripts\dungeondraft-mcp.exe` 的**绝对路径**。例如配置文件中的命令字段应是该可执行文件的完整路径。
4. 重启 MCP 客户端并在 Dungeondraft 中重新加载扩展。先调用 `ping`、`get_status`、`list_asset_categories` 检查连接和素材。

Linux/macOS 用户可将第二步命令替换为 `python3 -m venv .venv` 与 `.venv/bin/pip install -e ./server`，注册 `.venv/bin/dungeondraft-mcp`。

坐标单位是软件的世界像素，默认每格 256 像素。绘制前先用 `list_assets` 查出当前已加载素材的路径。图片导入需本地 PNG 的绝对路径；保存和导出也需绝对路径。保存到已有文件时会生成 `.mcp-backup` 备份。

## 0.3：空间校验

家具放置、图片导入、移动、缩放、旋转、复制、替换贴图与镜像，默认先检查**整个物件的占地轮廓**。检查覆盖墙体及其厚度、门口净空、其他物件、地图边界、指定房间和预留通道；新画的墙也不能穿过已有家具。发生冲突时返回原因与相关物件编号，在修改地图前拦截。

| 工具 | 用途 |
| --- | --- |
| `get_asset_footprint` | 读取素材实际尺寸与可见边界，帮助选择家具比例。 |
| `check_object_placement` | 预检位置，不修改地图。 |
| `validate_layout` | 检查当前楼层，返回问题类型与物件编号。 |
| `set_spatial_region` | 登记房间、通道或地形保护区。 |
| `remove_spatial_region` | 移除已登记的区域。 |

推荐顺序：先画建筑，沿墙内侧登记 `kind="room"` 的房间；放家具时传入 `region="酒馆"`，要求整个占地留在房间内。使用 `kind="clearance"` 预留通道，使用 `kind="protected"` 保护已完成的建筑或河岸，随后再绘制地形、洞穴、水域、材质和路径。保护区检查包含笔刷半径、悬崖宽度和栅格误差；存在保护区时，全层填充及地形槽贴图更换会被拦截，因为它们也会影响已经画好的区域。

桌面摆件、树冠叠放可以明确设置 `allow_overlap=True`，仍然检查墙体、门口和区域。墙饰、整图图片等特殊绘制可以明确设置 `spatial_check=False`；不能在普通家具被拒绝后自动关闭校验重试。散布工具会重新抽取无冲突的位置，空间不足时返回部分完成结果。高低地工具先预检填充与悬崖，但组合操作和批处理仍不是原子事务。

这是保守的二维检查：采用去除透明留白后的旋转矩形，无法读取透明信息时使用整张贴图边界。异形家具、U 形吧台和树冠可能误报；门窗依据素材名称区分，自定义窗户可能需要调整净空设置。校验不判断美术质量、角色是否能走通、真实三维高低或物理光照，也不会自动检查已有洞穴、水域、移动的路径或材质、屋顶及通用原生/UI/撤销操作。地形防侵入需要先指定保护区。

区域和物件所属房间保存在**当前打开地图的当前楼层会话**中，MCP 重连后仍在，重新打开地图后需要重新登记。每次受保护的修改都会读取最新布局；如果检查后布局又发生变化，软件端会拒绝旧检查结果。更新时需要同时安装两端，重新加载扩展并重连 MCP 客户端；协议版本为 18，工具数量为 76。

水域、材质的装饰边框与平滑效果尚未量测，建议扩大保护区以留出视觉缓冲。洞穴配色和贴图更换影响整层，有保护区时也会被拦截。

## 测试与限制

新增公开样例：[余烬秘库地下大厅](examples/embervault-ai/README.zh-CN.md)。包含可编辑原生地图、无网格／网格成图、11 类透明自生成素材及完整提示词、中英文绘制过程、布局记录和实机检查脚本，不需要外部素材包。采用美观优先比例，保留四角向下旋转楼梯与 16 个原生光源。

![余烬秘库预览](examples/embervault-ai/preview.png)

`modify_wall` 修复了编辑墙体时丢失挂载门窗的问题。移动已有顶点时保留门窗编号、在墙段上的相对位置、朝向、贴图、宽度和开闭状态；带门窗墙体的顶点数量／闭合／类型／接头变化，以及缩短到容不下门窗的操作，会在修改颜色、贴图或几何之前拒绝。需要改变拓扑时，应明确移除并重新安装门窗。

保持软件窗口可见，执行 `python tests/live_wall_portals.py --run-live` 可运行独立门窗实机回归。脚本先保存恢复副本，加载测试副本，结束后恢复先前地图；恢复副本保留在系统临时目录，编辑器随后指向该副本，原文件保留。

离线回归：`\.venv\Scripts\python.exe -m unittest discover -s tests -v`。在 Dungeondraft 1.2.0.1 上已发现并逐项成功调用全部 71 个 MCP 工具；三层测试地图完成了绘制、保存、重开以及 PNG、JPEG、WEBP、Universal VTT 导出。测试地图用到用户自己的素材包，未随公开仓库分发。

0.3 版另通过 30 项离线回归和 28 项实际软件空间验证，MCP 标准输入输出发现 76 个工具，5 个新增空间工具均完成实际 MCP 调用。被拦截的物件/墙体操作前后布局一致，地形/洞穴/水域操作也比较了原生数据。实测覆盖检查结果过期、透明图片边界、贴图替换、镜像和复制；结束后重开原地图，清理全部测试物件。

地形高低通过楼层、叠放层、悬崖和灯光表现；当前接口不提供可编辑的三维地形高度场。灯光使用 Dungeondraft 的二维光照系统，支持遮挡与距离衰减，不能据此宣称真实三维光线追踪或严格的反平方定律。

灯光的 `range` 是贴图缩放倍数，通常从 1～3 开始，不能填世界像素距离。每盏灯应对应可见的灯具或火堆。家具还要放在地板之上的绘图层：例如地板为 100 时，可在该层存在的情况下用 `set_element_layer` 将家具设为 150。几何校验不能发现家具被地板遮住或灯光范围过大，必须导出图片检查，并在保存重开后复核。

0.3.1 修复了 Godot 3 对带透明度颜色的通道顺序差异：MCP 的 `#rrggbbaa` 会转换成明确的 RGBA 分量，普通颜色结果也采用相同顺序；原生检查与地图文件继续保留 Godot 的 ARGB 格式。该修补通过 31 项离线测试，并在实际地图重新布置时核对了颜色通道。

当前软件版本的原生 Universal VTT 导出有时只留下临时 PNG。MCP 会结合软件导出的图片与原生地图数据生成可用的 `.dd2vtt`，保留墙体视线阻挡、门窗、环境光和独立灯光。这个替代导出尚未把洞穴边缘与物件剪影转成 VTT 视线阻挡线。

更多接口、通信协议和开发细节见 [英文 README](README.md) 与 [PROTOCOL.md](PROTOCOL.md)。
